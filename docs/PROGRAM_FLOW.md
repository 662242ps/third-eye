# Third Eye - Program Flow

เอกสารนี้อธิบายการไหลของข้อมูลตั้งแต่เปิดโปรแกรมจนถึงการแจ้งเตือน โดยแบ่งเป็น 6 ช่วงหลัก

## 1. เริ่มโปรแกรม

```text
main.py
  -> ตั้งค่า environment ของ Qt, OpenMP, MKL และจำนวน thread
  -> โหลด PyTorch ก่อน PyQt เพื่อช่วยลดปัญหา DLL ชนกันบน Windows
  -> สร้าง QApplication
  -> สร้าง MainWindow
```

ถ้า dependency หรือโมเดลสำคัญโหลดไม่ได้ โปรแกรมจะแสดงข้อความสาเหตุแทนการปิดเงียบ ๆ

## 2. เตรียมระบบ

`MainWindow` โหลดค่าจากไฟล์เหล่านี้:

```text
settings/alert_settings.json       เสียงไซเรนและเสียงพูด
settings/camera_settings.json      index กล้องภายในและ Focal Length
settings/object_heights.json       ความสูงโดยประมาณของวัตถุแต่ละชนิด
settings/distance_thresholds.json  ระยะอันตรายและระยะระวัง
settings/model_settings.json       โมเดล YOLO ที่เลือก
zones/active.txt                    จุดโซนตรวจจับ
```

จากนั้นสร้าง worker สำหรับ YOLO และโหลดโมเดลใน worker แยกจาก UI พร้อม warm-up หนึ่งครั้งก่อนรับงานจริง เสียงแจ้งเตือนจะใช้ไฟล์ WAV segment ที่เตรียมไว้แล้ว ไม่โหลดโมเดล TTS ในลูปวิดีโอ

## 3. รับแหล่งภาพ

```text
กล้อง  -> CaptureThread อ่านภาพต่อเนื่องและเก็บเฉพาะเฟรมล่าสุด
วิดีโอ -> อ่านเฟรมตามตำแหน่ง playback และรองรับการเลื่อนเวลา
รูปภาพ -> โหลดภาพที่เลือกและประมวลผลเป็นชุด
```

การเก็บเฉพาะเฟรมล่าสุดช่วยไม่ให้คิวภาพเก่าค้าง เมื่อโมเดลประมวลผลช้ากว่ากล้อง

## 4. เตรียมภาพและตรวจจับ

```text
ภาพต้นฉบับ
  -> แสดงบนหน้าจอด้วยสัดส่วนเดิม
  -> letterbox ลงในภาพ 640x640 โดยเติมขอบ ไม่ยืดภาพ
  -> ส่งเข้า YOLO
  -> รับกรอบวัตถุ class และ confidence
  -> แปลงพิกัดกรอบกลับไปยังภาพต้นฉบับ
```

จึงได้ผลลัพธ์ 2 ระบบพิกัดที่ทำงานร่วมกันได้:

- หน้าจอ: ภาพต้นฉบับเต็มขนาด
- โมเดล: อินพุตคงที่ 640×640

## 5. กรองโซน คำนวณระยะ และจัดระดับ

```text
กรอบวัตถุ
  -> ตรวจจุดอ้างอิงของวัตถุว่าอยู่ในโซนหรือไม่
  -> ประเมินระยะจากขนาดวัตถุ, ความสูงโดยประมาณ และ Focal Length
  -> เปรียบเทียบกับ distance_thresholds.json
```

กติกาการจัดระดับ:

```text
distance <= danger   -> DANGER / อันตราย
distance <= warning  -> WARNING / ระวัง
distance > warning   -> SAFE / ปลอดภัย
```

จากนั้นระบบจะลดการสั่นของผลตรวจจับด้วย smoothing/tracking และเลือกสถานะที่สำคัญที่สุดเมื่อมีหลายวัตถุ

## 6. แสดงผลและแจ้งเตือน

```text
ผลตรวจจับ
  -> วาดกรอบและข้อความบนภาพ
  -> อัปเดตรายการแจ้งเตือน
  -> อัปเดตจำนวน อันตราย/ระวัง/ปลอดภัย
  -> อัปเดต FPS และสถานะระบบ
  -> ส่งสถานะที่ใกล้/รุนแรงที่สุดไปยังเสียง
```

ลำดับเสียง:

```text
DANGER  -> ไซเรนดังและถี่กว่า + เสียงพูดอันตราย
WARNING -> ไซเรนเบาและห่างกว่า + เสียงพูดระวัง
SAFE    -> ไม่ส่งเสียง
```

เสียงพูดถูกประกอบจากไฟล์ WAV segment ตามสถานะ ชนิดวัตถุ และจำนวนเมตร แล้วเล่นใน worker เสียงแยกจาก UI มีการหน่วงและตรวจการเปลี่ยนระยะก่อนพูดซ้ำ เพื่อไม่ให้เสียงพูดซ้ำทุกเฟรม

## 7. การหยุดระบบ

เมื่อกด **หยุด** หรือปิดหน้าต่าง:

```text
หยุดรับภาพ
  -> หยุด CaptureThread
  -> หยุด YoloThread และรอให้จบงาน
  -> ปล่อย VideoCapture
  -> หยุดไซเรนและเสียงพูด
  -> เคลียร์สถานะ UI ตามความเหมาะสม
```

ลำดับนี้ช่วยลดปัญหากล้องถูกล็อก, thread ค้าง และเสียงเล่นต่อหลังปิดระบบ

## 8. จุดควบคุมตามไฟล์

| ส่วน | ไฟล์หลัก | สิ่งที่ควบคุม |
|---|---|---|
| เริ่มระบบ | `main.py` | dependency, environment, QApplication |
| UI | `ui/main_window.py` | ปุ่มหลัก แหล่งภาพ การแสดงผล และ lifecycle |
| ตั้งค่า | `ui/settings_window.py` | ระยะ โซน กล้อง โมเดล และเสียง |
| รับภาพ | `vision/capture_thread.py` | กล้อง วิดีโอ เฟรมล่าสุด และการหยุด |
| AI | `vision/yolo_thread.py` | YOLO 640×640, tracking, ระยะ และ risk |
| พิกัดภาพ | `vision/frame_utils.py` | letterbox และแปลงพิกัดกลับ |
| ไซเรน | `vision/alert_sound.py` | เสียง WARNING/DANGER และ priority |
| เสียงพูด | `vision/voice_alert.py`, `vision/voice_segments.py` | ต่อ WAV segment ภาษาไทย ระดับเสียง และการลดการพูดซ้ำ |
| ความสูงวัตถุ | `vision/object_height_config.py` | ค่าความสูงโดยประมาณสำหรับคำนวณระยะ |
| ไฟล์เสียง | `assets/voice/segments/` | เสียงที่เล่นจริงระหว่างตรวจจับ |
| ค่าถาวร | `settings/`, `zones/` | ค่าที่ผู้ใช้บันทึก |

## 9. จุดตรวจสอบเมื่อมีปัญหา

1. ดูสถานะด้านล่างของหน้าหลักว่าโมเดลพร้อมหรือไม่
2. ตรวจ `python -m pip check`
3. ตรวจว่าแหล่งภาพเปิดได้และมีเฟรมจริง
4. ตรวจ `settings/model_settings.json` และไฟล์ `.pt`
5. ตรวจ `zones/active.txt` ว่ามีจุดอย่างน้อย 3 จุด
6. ตรวจค่า danger < warning
7. ตรวจการเปิดเสียงทั้งที่หน้าหลักและหน้าตั้งค่า
8. ตรวจไฟล์เสียงใน `assets/voice/segments/` และรัน Unit Test ก่อนเปลี่ยนแปลงส่วนอื่น
